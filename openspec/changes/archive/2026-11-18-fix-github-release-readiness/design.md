# Design

## Context

沿用现有协议、模型客户端和执行后端。评审中的独立复现是修复起点；不增加生产依赖。全部 13 项问题按 proposal 与 tasks 追踪。

## Goals / Non-Goals

目标是关闭已复现边界并恢复可复现的离线门禁。非目标包括外网服务、多租户、后端重写、真实模型评估和发布操作。

## Decisions

- 现有 `.forgeagent/receipts` 保留位置和数据，成为模型工具不能读写或移动的宿主保留区域，避免引入新 HOME 写入及隐式迁移。restricted 审计钩子与 File 工具拒绝访问；container 使用只读覆盖挂载保护目录及其父目录绑定。仍保持 restricted 不是 OS 安全边界的说明。持久动作目录记录已创建 ID，记录缺失或目录不一致 fail closed；旧有效回执在安全初始化中登记，不重放动作。
- 文件读取只接受已打开的普通文件并有字节上限，超限返回稳定失败；无需新增分页 API，既有 Exec 可处理大文件。Skill 读取上限在解码前生效，图片在第 21 张时停止。
- worker stdout/stderr 保留固定头部并标记截断；父进程排空管道且限制帧大小，状态也受帧大小约束。输出超限不能让宿主无限分配内存。
- 工作目录与权限根分离：任务始终在项目目录运行，即使获准扩大文件权限；内建执行器默认工作目录为其 allowed_root。
- 原始工具名和 HTTP 枚举字段先验证类型；模型正文、工具结果以字面文本呈现。
- SDK 关闭自身重试，保留统一重试记录。模型发现使用有限短超时和确定性关闭，缓存验证结构并原子写入；无效缓存视为未命中。
- GitHub CI 复用现有门禁，使用固定 OpenSpec 版本，与开发文档和 GitLab 保持一致。历史证据完整性改由当前受版本控制的摘要证明，不依赖历史 Git 对象。

## Risks / Trade-offs

- 保留区域是应用层控制，trusted 同进程执行及恶意宿主不具有隔离保证；文档明确其边界。
- 新增读取/输出上限可能使原来返回超大内容的调用失败或截断；返回值明确披露，不伪造完整结果。
- Docker 本机不可用时仅记录未验证，CI 配置要求真实测试零跳过；不把配置写成已运行证据。
- 旧回执初始化保留文件；登记完成后缺失记录停止执行。不得自动清空、解决或重放旧动作。

## Migration Plan

原路径和回执 schema 保留；新增目录登记文件并验证现有记录。升级无外部副作用。回滚需保留目录登记及所有原回执；禁止为恢复执行而删除未知回执。
