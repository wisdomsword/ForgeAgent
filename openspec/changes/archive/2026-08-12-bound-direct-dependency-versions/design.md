## Context

`pyproject.toml` 中 `pydantic`、`anthropic`、`jinja2`、`rich`、`pyyaml`、`mcp`、`pytest` 和 `ruff` 仅声明最低版本。已有 `openai>=2.24,<3` 与 `prompt-toolkit>=3.0,<4` 已采用主版本上界，说明项目倾向在显式评估后再跨越不兼容主版本。

## Goals / Non-Goals

**Goals:**

- 让所有直接依赖具有明确、可审计的兼容范围。
- 保持当前锁定版本不变，只更新约束元数据。
- 让依赖契约测试与实际声明一致。

**Non-Goals:**

- 不升级或降级任何已锁定包。
- 不引入新的依赖管理抽象或自动更新服务。
- 不修复与依赖声明无关的测试或运行时行为。

## Decisions

1. 依照语义化版本的兼容边界，为当前 0.x 工具依赖 `ruff` 使用 `<1`，其余依赖使用下一个主版本上界。
2. `rich` 当前支持范围收敛为 `>=13.0,<16`，保留当前锁定主版本，同时阻止未经验证的后续主版本。
3. 通过 `uv lock` 更新锁文件中的直接依赖 specifier；若解析结果出现版本变动，则先审查原因，不接受无关升级。
4. 更新现有依赖集合精确断言，不新增重复测试入口。

## Risks / Trade-offs

- [上界过窄导致未来升级需人工修改] -> 这是有意门禁；跨主版本升级必须经过显式验证。
- [锁文件发生无关版本漂移] -> 审查 `uv.lock` diff，只接受 specifier 变化。
- [依赖元数据测试固化旧字符串] -> 同步更新既有精确断言，保持单一契约。
