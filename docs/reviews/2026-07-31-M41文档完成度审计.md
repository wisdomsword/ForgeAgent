## 3. 未尽事宜与建议

### P1：历史 OpenSpec Purpose 规范化

修正 M41 后，仍有 22 个历史主规格保留 OpenSpec 自动归档生成的 `TBD` Purpose。它们不影响 M41 运行时正确性，但会降低规格检索和评审质量。

建议建立一个独立的文档维护 change，逐个从已归档 proposal/requirements 提炼一到两句 Purpose，并增加离线检查，禁止新归档主规格继续保留该占位符。该 change 不修改 requirement、scenario 或运行时源码，不与 Memory、HTTP 或 Rewrite 功能混做。

### 条件候选：保持触发式立项

- 既有 Memory 元数据迁移：只有出现真实持久化迁移需求和恢复 verifier 时立项。
- 未来新的 Rewrite/依赖变更：继续逐项执行 M32 六项门禁；M41 的成功不能自动授权下一次重构。
- HTTP 远程动作审批绑定：只有出现外部 HTTP 动作控制面并能验证 action digest/scope 绑定时立项；当前服务仍为 loopback-only。

### 不建议立项

- 不为 `cli.py` 的 11 行余量单独建立里程碑；由结构测试和代码评审持续守门即可。
- 不恢复包索引发布、正式 tag、远程 push 或发布自动化。
- 不把浏览器、桌面、远程 Skill 供应链等无真实触发场景的能力提前纳入主线。
