# Subagent 任务模板（M1 设计文档）

> 来源：ACTION_PLAN.md §三 item 6，本文档只是把已裁决的内容抽成独立可复用的一页模板，不新增设计。
> **归属（B1 裁决）**：本模板属**开发 harness**——即 Claude Code 在开发 ForgeAgent 期间派发编码/测试子任务时用的契约。它与 ForgeAgent 的**运行时协议**（`text-protocol-spec.md`）无关；运行时协议 v1 已不含 SubTask 工具。两者只是碰巧都叫 "subagent/subtask"，不要相互引用或复用字段。
> 边界：subagent 只做编码与测试，不做架构决策——呼应 spec.md 的算力分配原则（小任务交给便宜模型，重任务保留全力运行）。派发前必须自问：这是不是架构/方案决策？是→主 Agent 自己做；不是→可以派发。

## 派发前检查

- [ ] 任务是否可以用一句话说清"完成后长什么样"（验收标准）？说不清就不该派发。
- [ ] 是否需要主 Agent 事先决定架构/接口/命名等设计问题？需要→先决定完，再把结果作为约束传给 subagent。
- [ ] 选哪个模型？**默认 `claude-sonnet-5`**；仅明确的小任务（机械改名、单文件小改、格式化等）才降到廉价的 `claude-haiku-4-5`。这修订了初稿"默认便宜模型"的表述——重任务保留 sonnet-5 全力，呼应 spec.md 的"重任务保留全力运行"（参见 `model-capability-matrix.md` 的开发期 subagent 模型选择）。

## 任务包结构（派发时填写）

```markdown
## 上下文包
- 相关文件：<路径列表，或"见 codegraph_explore 结果">
- 已知约束：<接口签名 / 命名规范 / 禁止修改的文件等>
- 不要做的事：<明确排除项，防止 subagent 自行扩大范围>

## 目标
<一句话说清要交付什么>

## 强约束
- 遵循 CLAUDE.md 的命名规则（描述性英文命名，禁止缩写）
- 遵循项目现有代码风格（<具体指向：如 ruff 配置 / 现有模块写法>）
- <本任务特有的其它约束>

## 验收标准
- [ ] <可验证的具体标准，如"pytest tests/xxx 全部通过">
- [ ] <如"不引入新依赖" / "不修改 resource/agent/ 下任何文件">

## 返回格式（五项固定字段，缺一不可）
1. **改动摘要**：改了哪些文件、做了什么，一两句话。
2. **测试结果**：运行了什么命令，原样贴输出（不得转述"测试通过"，必须给证据）。
3. **未验证项**：明确说明哪些部分没有跑起来验证过、为什么。
4. **偏离计划项**：如果实现和任务包描述不一致，说清楚哪里不一致、为什么。
5. **需要主 Agent 决策项**：遇到任何超出授权范围的判断（架构/接口/取舍），列出来，不擅自决定。
```

## 为什么是这五项（呼应 spec.md）

- 改动摘要 + 测试结果 → 对应 spec.md「结论先行」「实证汇报」：先说结果，测试失败原样贴输出，不编造进度。
- 未验证项 → 对应「实证汇报」的另一半：没验证的必须说没验证。
- 偏离计划项 → 让主 Agent 能发现 subagent 是否越权做了架构决策（违反"只做编码与测试"边界）。
- 需要主 Agent 决策项 → subagent 遇到设计问题时应该停下来报告，而不是自己拍板——这是边界的强制执行点，不是建议。

## 主 Agent 收到返回后的处理

1. 先看"需要决策项"——如果有，先做决策，可能需要重新派发。
2. 核对"测试结果"是否真的是命令输出（而非转述），存疑就自己跑一遍验证。
3. "偏离计划项"非空时，评估是否可接受；不可接受则打回重做，说明原因。
4. 全部通过才可标记任务完成，不可只凭 subagent 自称"完成"就采信。
