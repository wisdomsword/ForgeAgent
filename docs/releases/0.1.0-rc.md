# ForgeAgent 0.1.0 Release Candidate

## 状态

这是 ForgeAgent `0.1.0` 的 Release Candidate，不是正式发布。候选包尚未发布到包索引，
也没有以正式版本 tag 或上传记录作为完成证据。

## 安装

在 Python 3.11 或更高版本中，从本地构建产物安装候选 wheel：

```bash
python -m pip install dist/forgeagent-0.1.0-py3-none-any.whl
forgeagent --help
```

## 已交付能力

- CLI：提供 `forgeagent` console script、单次任务、交互 loop、离线目录探针和本地服务入口。
- HTTP：提供本机 headless 任务的提交、查询和取消生命周期。
- 协作：支持显式 Single、Duo 和 Triad；Duo 包含 Generator/Evaluator，Triad 额外冻结 Planner 计划。
- 运行时：提供 restricted/container sandbox、Memory、Skills 和 Loop；具体信任边界仍以现有安全文档为准。

## 正式发布阻塞条件

以下条件全部满足前，`0.1.0` 仍是候选版本：

1. required Linux Docker job 对当前候选 wheel 成功运行十项 container integration 与六项 installed-wheel smoke，并发布有效 JUnit 和 `rc-smoke.json`；
2. 当前候选完成 Ruff、Golden 20/20、OpenSpec strict 与 build 验证；全量 pytest 必须全绿，或其中失败经已批准 change 明确裁决并关闭后重跑验证，不能仅以记录失败代替门禁关闭；
3. 独立审查与两轮最终一致性复审没有未解决的阻塞发现；
4. 正式发布动作另行执行并留下可核验的 tag 与上传证据，不能由 RC 文档代替。

当前第 2 项已满足；仍开放的是当前候选的 required Linux job 证据、最终审查/归档，以及另行授权的
tag/上传动作。

## 已知限制

### 平台证据

当前 M28 Linux installed-wheel gate 只是 configured/pending。M24 Pipeline 50 / Job 249 只证明当时的
Linux Docker runner container topology；macOS Docker Desktop 仅是 supplemental，均不能外推到其他
Linux 架构、rootless Podman 或 Windows。

### 真实模型

RC harness 使用确定性 `MockClient`，不访问真实 provider。真实模型 smoke 是显式 opt-in，会读取凭据、
产生外部请求与费用，且不属于离线 RC 门禁；未执行时不能把凭据存在写成通过。

### sandbox

restricted 不是 OS 级密封沙箱；它是应用层审计和进程边界，不能抵御恶意 Python/native escape。
container tier 提供更强隔离，但仍依赖 Docker daemon、固定镜像和宿主配置，不等同于通用多租户安全边界。

### HTTP

HTTP 默认只允许 loopback bind（`127.0.0.1` 或 `::1`），并要求 Bearer token；当前不提供 TLS，也不支持安全的公网、反向代理或
多租户暴露。请求不能覆盖 sandbox、凭据、路径或其他服务端信任策略。

### 协作 v1

协作 v1 提供 Single/Duo/Triad 的结构化提交和冻结检查绑定，但没有协作专用 resume endpoint。
Loop resume 仍通过既有任务提交字段 `resume_loop_id` 发起。headless Triad 计划策略默认拒绝自动批准，
只有服务端显式配置 preauthorize 才可继续；任务文本和普通请求不能伪造可信宿主已绑定的冻结检查。
