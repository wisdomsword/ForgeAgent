# ForgeAgent 0.1.0

## 状态

ForgeAgent `0.1.0` 的正式发布暂缓。候选已通过本地和 required Linux Docker 技术门禁，但仍需
人类实践和易用性优化；当前未上传 PyPI，未创建 `v0.1.0` tag。本页记录正式发布前仍需满足的门禁
和已知限制，不代表公开发行已经完成。

公开安装前可按候选说明从本地 clean wheel 验证，步骤见 [`0.1.0-rc.md`](0.1.0-rc.md)。在生产
PyPI 与远端 tag 完成回读前，不提供生产 PyPI 安装命令。

## 已交付能力

- CLI：提供 `forgeagent` console script、单次任务、交互 loop、离线目录探针和本地服务入口。
- HTTP：提供本机 headless 任务的提交、查询和取消生命周期。
- 协作：支持显式 Single、Duo 和 Triad；Duo 包含 Generator/Evaluator，Triad 额外冻结 Planner 计划。
- 运行时：提供 restricted/container sandbox、Memory、Skills 和 Loop；具体信任边界以安全文档为准。

## 已知限制

### 平台证据

required Linux Docker job只验证其记录的 Python、Linux runner、架构与 Docker topology，不能外推到
其他 Linux 架构、rootless Podman 或 Windows。macOS Docker Desktop 证据仅是 supplemental。

### 真实模型

发布门禁使用确定性 `MockClient`，不访问真实 provider。真实模型 smoke 是显式 opt-in，会读取凭据、
产生外部请求与费用，且不属于离线 required 门禁；未执行时不能把凭据存在写成通过。

### sandbox

restricted 不是 OS 级密封沙箱；它是应用层审计和进程边界，不能抵御恶意 Python/native escape。
container tier 提供更强隔离，但仍依赖 Docker daemon、固定镜像和宿主配置，不等同于通用多租户安全边界。

### HTTP

HTTP 默认只允许 loopback bind（`127.0.0.1` 或 `::1`），并要求 Bearer token；当前不提供 TLS，也不支持
安全的公网、反向代理或多租户暴露。请求不能覆盖 sandbox、凭据、路径或其他服务端信任策略。

### 协作 v1

协作 v1 提供 Single/Duo/Triad 的结构化提交和冻结检查绑定，但没有协作专用 resume endpoint。
Loop resume 仍通过既有任务提交字段 `resume_loop_id` 发起。headless Triad 计划策略默认拒绝自动批准，
只有服务端显式配置 preauthorize 才可继续；任务文本和普通请求不能伪造可信宿主已绑定的冻结检查。
